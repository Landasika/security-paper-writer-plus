# Security Paper Section Templates

## Abstract Template

```
[Problem Statement] is a critical security concern in [Domain]. 
Existing solutions suffer from [Limitation1] and [Limitation2].

In this paper, we present [System/Method Name], a novel approach 
to [Security Goal]. Our key insight is [Insight].

We evaluate [System/Method] on [Dataset/Platform] with [Scale]. 
Results show that our approach achieves [Metric1] (X% improvement) 
and [Metric2] (Y% reduction), while introducing only Z% overhead.

Our findings have significant implications for [Impact Domain].
```

## Introduction Template

### Opening (Security Impact)

```
[Technology/System] has become ubiquitous in [Domain], with over 
X [users/deployments] worldwide. However, this widespread adoption 
has introduced serious security vulnerabilities that [consequence].
```

### Problem Statement

```
Recent studies have revealed that [Vulnerability] affects X% of 
[Systems]. Attackers can exploit this to [Attack Impact], leading 
to [Real-world Consequence].
```

### Limitation of Existing Work

```
While prior work has addressed [Aspect], these approaches share 
common limitations: (1) [Limitation1], (2) [Limitation2], and 
(3) [Limitation3].
```

### Our Approach

```
We propose [System Name], a [Category] approach that [Key Feature]. 
Unlike existing methods, our solution [Differentiation].
```

### Contributions

```
We make the following contributions:
• We identify/analyze [Contribution1] (Section X).
• We design/implement [Contribution2] (Section Y).
• We evaluate [Contribution3] on [Dataset] (Section Z).
• We release [Artifact/Data] to the research community.
```

## Threat Model Template

### Adversary Capabilities

```
We consider an adversary who [Capability Description]. 
The attacker can:
• [Capability1]: [Description]
• [Capability2]: [Description]
• [Capability3]: [Description]
```

### Attack Surface

```
The attack surface includes:
• [Component1]: [Vulnerability Description]
• [Component2]: [Vulnerability Description]
```

### Assumptions

```
We make the following assumptions:
• [Assumption1]: [Justification]
• [Assumption2]: [Justification]
```

### Out of Scope

```
The following are outside our threat model:
• [Exclusion1]: [Reason]
• [Exclusion2]: [Reason]
```

## Security Evaluation Template

### Metrics

```
We evaluate our system using the following metrics:
• [Metric1]: [Definition] (target: X)
• [Metric2]: [Definition] (target: Y)
• [Metric3]: [Definition] (target: Z)
```

### Attack Effectiveness

```
To assess attack effectiveness, we measure [Metric] under 
[Condition]. Our results show that [Finding].
```

### Defense Effectiveness

```
We evaluate defense effectiveness by [Method]. The system achieves 
X% detection rate with Y% false positive rate.
```

### Performance Overhead

```
We measure performance overhead on [Platform]. Our system introduces 
X% latency increase and Y% memory overhead, which is acceptable 
for [Use Case].
```

## Ethical Considerations Template


## Discussion Template (Limitations)

```

```
